# 대시보드 작업 규약

이 문서가 있는 이유: 매번 처음부터 설명하지 않기 위해서다.
아래 규칙은 이미 한 번씩 깨져서 사고가 났던 것들이다.

## 구조

| 경로 | 무엇 |
|---|---|
| `public/index.html` | 화면 전체. 단일 파일, 빌드 없음, 외부 라이브러리 없음 |
| `api/[resource].js` | **서버리스 함수 하나**. `RESOURCES` 맵에 항목 추가로 엔드포인트 추가 |
| `api/_supabase.js` | 공용 클라이언트 + `crudHandler` |

**함수 파일을 새로 만들지 말 것.** Vercel 무료 플랜 상한이 12개고 이미 그것 때문에
배포가 한 번 깨졌다. 새 테이블은 `RESOURCES` 맵에 한 줄 추가하면 끝이다.

`me_settings` 만 예외 — 기본키가 `key` 라서 `settingsHandler` 로 따로 처리한다.
새 설정 키를 추가하면 `SETTING_KEYS` 에도 넣어야 한다. 안 넣으면 조용히 무시된다.

## 색

검증된 3색만 쓴다. 색을 새로 추가하지 말고 그라데이션·발광·모션으로 화려함을 낸다.

| 변수 | 값 | 용도 |
|---|---|---|
| `--accent` | `#3987e5` | 진행 |
| `--streak` | `#d95926` | 연속 |
| `--done` | `#199e70` | 완료 |
| `--urgent` | `#d03b3b` | 급함 |
| `--track` | `#363b4d` | 진행 트랙 — `--card` 와 너무 가까우면 링이 안 보인다 |

구분은 색이 아니라 **아이콘 + 라벨**이 진다. 색맹 대응이기도 하고, 축이 여섯 개
넘어가면 어차피 색으로는 구분이 안 된다.

## 수치를 화면에 낼 때

- **비율보다 배수.** 목표 1억에 30만원이면 "0.3%" 가 아니라 "333배 남음". 매일 0.3%는
  아무것도 안 가르쳐준다.
- **단위를 올려라.** `perText()` 가 하는 일 — "하루 0kg" 이 나오면 주·월로 올려서
  숫자가 1 이상 되게 한다.
- **기준을 같이 적어라.** 65점만 띄우면 왜 65인지 모른다. "주 4회 기준" 을 붙인다.

## 블루록 층 구조 — 섞지 말 것

| 층 | 축 | 규칙 |
|---|---|---|
| 순위 F–S | 주간 산출 개수 **하나** | 절대 여러 지표를 섞지 않는다. 섞으면 운동만 해도 A가 나온다 |
| 능력치 | 여섯 축 | 진단용. 등급에 반영하지 않는다 |
| 메타비전 | 예측 vs 실제 적중률 | 7번째 축이 아니다. 종류가 다르다 |

단계(균형기 → 관측기 → 특화기)가 순서를 강제한다. 최저 축 40 미만이면 무기는
"가설" 로 표시된다.

## 신호 순위 — 공유 > 저장 > 도달

도달은 제일 약한 신호인데 제일 눈에 잘 띈다. 그래서 비교하는 화면(형식별, 무대
테스트)은 전부 `bestSignal()` 이 고른 축으로 매긴다 — 공유가 하나라도 적혀 있으면
공유, 없으면 저장, 그것도 없으면 도달. **도달 기준으로 되돌리지 말 것.**

형식(목록형·비교형·역설형·혼합형)은 형식당 3개 미만이면 왕관을 달지 않는다.
1개짜리 평균은 평균이 아니라 우연이다.

## CSS 클래스 이름은 먼저 grep 한다

`.chk` 를 새로 만들었다가 이미 있던 퀘스트 체크 버튼(`width: 22px`)에 걸려서
체크리스트 글자가 세로로 뭉갰다. 문법도 통과하고 콘솔 에러도 없었다 — 렌더를
안 봤으면 그대로 나갔다. 새 클래스는 붙이기 전에 `grep -n "\.이름" public/index.html`.

## 고칠 때 반드시 도는 순서

```bash
# 1. 문법
node -e "const fs=require('fs');[...fs.readFileSync('public/index.html','utf8')\
  .matchAll(/<script>([\s\S]*?)<\/script>/g)].forEach(x=>new Function(x[1]));console.log('ok')"

# 2. 폰 화면으로 실제 렌더 (390x844)
#    http 스텁 서버 + playwright-core, chromium 은 /opt/pw-browsers/chromium-*/chrome-linux/chrome
#    pageerror / console error 를 반드시 수집해서 0인지 확인
#    가로 오버플로 확인: document.documentElement.scrollWidth > window.innerWidth

# 3. 스크린샷을 눈으로 본다. deviceScaleFactor 는 1 (2로 하면 업로드가 막힌다)
```

렌더 확인 없이 커밋하지 말 것. 문법만 맞고 화면이 깨진 경우가 여러 번 있었다.

## 배포

```bash
git push -u origin claude/what-is-plugin-61ciph
git checkout main && git merge --ff-only claude/what-is-plugin-61ciph
git push origin main          # ← 이걸 빠뜨리면 배포가 옛 커밋을 계속 서빙한다
```

`main` 만 프로덕션에 나간다. 브랜치에만 푸시하고 "배포했다" 고 말한 적이 있는데,
그때 사이트는 안 바뀌어 있었다. 매번 `main` 까지 확인한다.

배포 후 Vercel 배포 목록에서 해당 SHA 가 `state: READY`, `target: production` 인지
확인하고, 라이브 HTML 에 새 함수 이름이 실제로 들어갔는지 grep 한다.

## 보안 — 예외 없음

- `service_role` 키는 **Vercel 환경 변수에만**. 채팅에 붙여넣지 않고, 깃에 커밋하지
  않고, 클라이언트 코드에 두지 않는다.
- 모든 `me_*` 테이블은 RLS 켜고 정책 없음. 서버에서 `service_role` 로만 접근한다.
- 사이트 자체가 Vercel Authentication 뒤에 있다.

## 설계할 때 지킨 것들

기능을 더할 때 이 판단들을 뒤집지 말 것. 이유가 있다.

- **또래 비교 안 넣는다.** 메타인지 표는 "나 vs 선임이 볼 나" 다. 동기 컬럼을 만들면
  실력이 아니라 원망을 쌓는다. 증거 칸은 필수 — 느낌만으로 점수를 못 매기게.
- **군 지식 내용은 대신 써주지 않는다.** 부대마다 다르고, 직접 쓰는 행위 자체가
  기억에 남는다. 틀에만 넣어준다.
- **런타임에 Claude 를 부르지 않는다.** 이 대시보드는 API 키 없이 돈다. 사용자가
  추가 과금을 원하지 않는다고 명시했다.
- **올리기 전 검사는 5개 중 4개가 통과선.** 다 채우라고 하면 안 채우고 올린다.
  통과 개수만 저장하고 어느 항목이었는지는 안 남긴다 — 이 칸의 일은 기록이 아니라
  올리기 전에 다섯 줄을 실제로 읽게 만드는 것이다. 그래서 수정 시트에서는
  체크박스 대신 숫자로 보여준다(없는 정보를 지어내지 않으려고).
- **연속 기록은 7일에 1일 유예.** 군 일정상 못 하는 날이 반드시 생긴다. 0으로
  리셋되면 두 번째 날에 앱을 버린다.
